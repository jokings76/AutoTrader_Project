```bash
run_dashboard.bat
```

```bash
python -m ui.server
```

## 이 폴더가 지켜야 하는 단 하나의 규칙

🔴 **`core/` · `main.py`를 절대 import하지 않는다.**

그래야 UI를 아무리 고쳐도 매매 로직과 15개 스위트 1,660건에 영향이 없다.
= **장중에도 UI만은 안전하게 수정할 수 있다.**

허용 의존은 둘뿐이다:
- `db.connection` — DB 설정(config.ini)·풀의 **단일 출처**. 여기서 복제하면
  이 코드베이스의 반복 사고 1위("같은 규칙이 여러 경로에 흩어져 조용히
  어긋난다")를 그대로 밟는다. 매매 로직이 아니라 읽기 인프라라 안전하다.
- 표준 라이브러리 + fastapi/uvicorn

이 규칙이 깨졌는지 확인:
```bash
python -c "import ast,pathlib;
bad=[(p.name,n.module or '') for p in pathlib.Path('ui').glob('*.py')
     for n in ast.walk(ast.parse(p.read_text(encoding='utf-8')))
     if isinstance(n,(ast.Import,ast.ImportFrom))
     and any(str(getattr(n,'module','') or '').startswith(m) or
             any(a.name.startswith(m) for a in n.names) for m in ('core','main'))];
print('위반:', bad or '없음')"
```

## 안전 설계

| # | 장치 | 내용 |
|---|---|---|
| 1 | **읽기 전용** | 쓰기 엔드포인트가 없고, DB 커넥션이 `readonly=True` 세션이라 실수로 UPDATE를 써도 **DB가 거부**한다 |
| 2 | **루프백 전용** | 기본 `127.0.0.1`. 실계좌 현황을 LAN에 노출하지 않는다. 바꾸려면 `AUTOTRADER_UI_HOST`를 명시해야 하고 그때 경고를 찍는다 |
| 3 | **별도 프로세스** | UI가 죽어도 봇은 살고, 봇이 죽어도 UI로 원인을 본다 |
| 4 | **패널 격리** | DB가 내려가도 각 패널이 자기 자리에 에러를 표시할 뿐 화면이 백지가 되지 않는다 |

## 🔴 데이터 함정 3가지 (실측으로 확인한 것)

### 1. 타임존이 테이블마다 다르다
```
trades.buy_time / sell_time   ->  로컬(KST)
system_events.timestamp       ->  UTC   (KST = +9h)
```
실측: 뉴엔AI 손절이 `trades`엔 `13:51:44`, `system_events`엔 `04:51:44`.
DB 세션 TimeZone이 UTC라서 그렇다. **섞으면 9시간 어긋난다** —
`queries._to_kst()`를 반드시 통과시킬 것. 날짜 필터도 UTC 경계로 걸어야
KST 하루가 온전히 잡힌다.

### 2. 추가매수는 `entry_reason`을 덮지 않는다
실측: 뉴엔AI가 17주 매수 → rescue-add 17주 → **총 34주**가 됐는데
`entry_reason`엔 최초 진입 문구만 있고 `entry_note`는 안 들어간다.
→ **물타기 발동은 `trades`로 셀 수 없다.** 1차 소스는 로그(`💧 물타기`),
보조는 `system_events`의 `BUY_ADD`다.

### 3. `watch_list_log`의 가격 컬럼은 대부분 NULL이다
`surge_rate` · `open_price` · `today_open` · `high_pct`가 전부 비어 있다
(08-11 실측). → **편입 시 등락률로는 아무것도 판정할 수 없다.**
체크리스트 0번이 "등락률 8% 이내" 대신 **조건식 이름 확인**으로 간 이유다.

## 체크리스트 판정 규칙

CLAUDE.md 「🔬 장중에 반드시 볼 것」 0~10을 자동 판정한다.

| 상태 | 뜻 |
|---|---|
| `정상` | 기대대로 |
| `주의` | 기준 근처 — 사람이 봐야 함 |
| `이상` | 문서가 "이상하면 X" 라고 한 조건에 해당 |
| `판정 불가` | **데이터가 없다** |

🔴 **`판정 불가`를 성실히 쓰는 것이 이 기능의 핵심이다.** 데이터가 없는데
초록불을 켜면 대시보드가 "괜찮다"고 거짓말을 하고, 그건 표가 없는 것보다
나쁘다. (스텁이 실물과 달라 감사가 '통과'로 거짓말한 사고가 08-09·08-10에
연달아 있었다.)

⚠️ **08-11 날짜로 열면 0번·3번이 `이상`으로 뜨는 것이 정상이다** —
그날은 옛 사양(옛 조건식 / 손절 -3%)으로 돌았다. 08-12부터 `정상`이어야 한다.

## 매매일지 (자동저장)

```bash
python daily_journal.py                 # 오늘 저장
python daily_journal.py 2026-08-10      # 특정 날짜
python daily_journal.py --backfill 30   # 최근 30일 중 거래가 있던 날 전부
python daily_journal.py --list          # 저장된 목록
```
저장 위치: `observations/journal/YYYYMMDD.json` (하루 약 33KB)

### 왜 필요한가 — DB만으로는 재현이 안 되는 것이 있다

DB는 매매 **기록**을 영구 보관하므로 과거 날짜 조회 자체는 언제든 된다.
문제는 **DB에 안 남는 것**이다:

- **물타기 발동 횟수** — 추가매수는 기존 `trades` 행에 합쳐지고 `entry_reason`을
  덮지 않는다. 유일한 흔적이 **로그**다.
- **수동 추가매수 감지 / 확인 전용 차단** — 로그에만 남는다.

그런데 **로그는 10MB에서 로테이션되어 사라진다**(실측: 08-07은 14:30에 로테이션).
며칠 지나면 그날 판정을 **원리적으로 재현할 수 없다.**
→ 장 마감 후 한 번, 로그가 살아있을 때 굳혀 둔다.

실제로 백필해보면 과거로 갈수록 `판정 불가`가 늘어난다 — 로그가 이미 사라졌기
때문이고, **그게 정확한 상태다**(0으로 뭉개지 않는다):

```
2026-08-11  [정상 7 주의 1 이상 2 판정불가 1]   <- 로그 살아있음
2026-07-30  [정상 3 주의 1 이상 2 판정불가 5]   <- 로그 소실
```

### 대시보드와의 관계

| 날짜 | 체크리스트 소스 | 표시 |
|---|---|---|
| **오늘** | 항상 **실시간 계산** (스냅샷은 마감 후에 생긴다) | `실시간` |
| **과거 + 스냅샷 있음** | **스냅샷 우선** — 로그가 살아있을 때 굳힌 값이라 더 정확하다 | `📔 저장된 일지` |
| 과거 + 스냅샷 없음 | 실시간 계산 (로그 기반 항목은 `판정 불가`) | `실시간` |

상단 `저장된 일지…` 드롭다운으로 저장된 날짜로 바로 점프한다.

### 스케줄러 등록 (선택)

```
schtasks /Create /TN "AutoTrader_Journal" /SC DAILY /ST 15:40 ^
  /TR "cmd /c cd /d C:\AutoTrader_Bot\ProjectRoot && python daily_journal.py"
```

지금은 **Phase 0(관측)**만 있다. 전략을 UI에서 바꾸려면:

| Phase | 내용 | 봇 코드 변경 | 위험 |
|---|---|---|---|
| **0 (지금)** | 읽기 전용 대시보드 | **0줄** | **0** |
| 1 | 등급 1 파라미터 토글 (`strategy_overrides` 테이블 + `task_config_watch` + `apply_overrides()` 단일 관문) | 태스크 1 + 함수 1 | 낮음 |
| 2 | 등급 2 (익절캡·손절 — 영향 범위 경고 필수) | 관문 확장 | 중 |
| 3 | 조작 버튼(수동 청산 등) | 큼 | **높음** |

🔴 **Phase 1의 핵심 사실**: `strategy_manager.py`는 상수를 **메서드 안에서
모듈 전역으로** 읽는다(`if AVG_DOWN_ENABLED and ...`). 파이썬 전역 조회는
호출 시점에 동적으로 일어나므로 **`setattr(module, name, value)`가 재시작 없이
즉시 먹는다.** `self.X = X`로 박아둔 게 없어서 가능하다.

단 두 가지 예외가 설계를 지배한다:
- **파생 상수**: `TAKE_PROFIT_CAP = EXIT_POLICY["default"]["take_profit_cap"]` —
  딕셔너리를 고쳐도 안 바뀐다. 화이트리스트는 *실제로 읽히는 잎*을 겨냥할 것.
- **포지션에 박히는 값**: `pos["stop_rate"]`는 매수 시점 1회 계산 →
  손절 상수를 바꿔도 **보유 중인 종목엔 안 먹는다**(신규 매수분부터).

그리고 관문의 불변식은 **새로 짜지 말 것** — `audit_20260805.py` /
`audit_deep_20260808.py`에 이미 들어 있는 것을 재사용한다.
