\### 08:59 자동 기동 시 원격제어 세션 동시 실행 (2026-08-02 신규)
작업 스케줄러가 봇을 띄울 때 **별도 창으로 `claude --remote-control` 세션도
같이 시작**한다. 장중에 PC 앞에 없어도 폰에서 상태를 물어볼 수 있게 하는 용도.

- `start_trader.bat`이 `main.py`보다 **먼저** `start`로
  `start_remote_control.ps1`을 띄운다. `start`는 즉시 반환하므로 봇 기동을
  막지 않고, 봇이 죽어도 원격제어는 살아있어 원인 진단이 가능하다.
- 세션 이름을 `autotrader`로 고정했다 — 자동 생성 이름(`remote-control-keen-thimble`
  같은 것)은 매번 바뀌어 폰 앱 목록에서 찾기 번거롭다.

**이 조합에서 실제로 밟은 함정 4가지 (다시 건드릴 때 반드시 확인):**
1. `.ps1`을 **BOM 없는 UTF-8로 저장하면 안 된다.** PowerShell 5.1이 cp949로
   읽어 한글이 깨지고 `string is missing the terminator` 구문 오류가 난다.
   UTF-8 **BOM 필수**. (편집 도구가 BOM을 떼는 경우가 있으니 저장 후 재확인)
2. `.bat`에는 **주석이라도 한글을 넣지 말 것** — 2026-07-28에 겪은 것과 같은
   원인으로 깨진다. 비ASCII 0바이트인지 확인하고 커밋할 것.
   한글 경로 처리는 전부 `.ps1` 안으로 몰아넣었다.
3. claude의 **폴더 신뢰 승인은 '실제 경로' 기준**으로 저장돼 있다. junction
   경로(`C:\AutoTrader_Bot\ProjectRoot`)로 시작하면 다른 폴더로 보고 신뢰
   프롬프트를 다시 띄울 수 있는데, 무인 기동에서 프롬프트가 뜨면 거기서 멈춘다.
   -> `.bat`은 ASCII junction만 참조하고, `.ps1`이 **실제 경로로 Set-Location**.
4. `scheduler_debug.log`는 cmd.exe가 ASCII로 쓰는 파일이라 한글(UTF-8)을 섞으면
   한 파일에 두 인코딩이 공존해 전부 깨져 보인다.
   -> 파일에 남기는 로그는 ASCII, 화면 출력만 한글로 분리했다.

수동으로 원격제어만 띄우고 싶을 때:
```
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\AutoTrader_Bot\ProjectRoot\start_remote_control.ps1"
```

\### 모바일 원격 제어 (PC 세션을 폰에서 조작)
```
cd "C:\Users\rober\OneDrive\문서\vscode\AutoTrader_Project"
claude --remote-control
```
- ⚠️ **`claude remote-control`(하위명령)이 아니라 `--remote-control`(플래그)이다.**
  공식 문서 표기와 다르니 주의. 세션 중이면 `/rc`로도 가능.
- 실행하면 `https://claude.ai/code/session_XXXXXXXX` 형태의 URL이 뜬다.
  폰 Claude 앱 또는 폰 브라우저로 그 URL을 열면 연결된다.
- 폰 앱에서는 **[코드] 탭 → 세션 카드(예: `remote-control-keen-thimble`,
  `🖥 연결됨 · jokings76/AutoTrader_Project`)를 탭**해야 채팅창으로 들어간다.
  목록 화면만 보고 "연결이 안 됐다"고 오해하기 쉬움.
- **코드 실행·파일 접근은 전부 PC에서** 일어난다(클라우드 실행 아님).
  따라서 PC가 켜져 있고 **그 터미널 창이 열려 있어야** 하며, 창을 닫으면 끊긴다.
- 모바일에서는 **새 MCP 서버를 추가할 수 없다** — 필요한 건 PC에서 미리 세팅.
- 원격 세션은 기본 Sonnet 5로 시작한다. 전략 로직처럼 복잡한 작업은
  세션에서 `/model` 입력해 **Opus 5로 바꾸고 진행할 것**.
- ⚠️ **실거래 봇이 돌고 있는 장중에 모바일에서 매매 로직 파일을 고치지 말 것.**
  고칠 거면 이 문서 "작업 방식"의 surgical 패치 + import 검증 규칙을 그대로 지킨다.

\#### 세션 연속성 — 매일 전날 대화를 이어간다 (2026-08-02 변경)
`start_remote_control.ps1`이 기본으로 **`--continue`**를 붙인다. 08:59 자동기동도,
장중 자동재시작도 전부 직전 대화를 그대로 이어받는다. 폰 앱에 뜨는 URL은 매번
새로 생기지만 **대화 내용은 이어진다**(세션 이름 `autotrader` 고정).

- **대화가 길어져 한도가 걱정될 때**: 세션 안에서 "이관작업 해줘"라고 요청해
  CLAUDE.md에 맥락을 정리시킨 뒤, 프로젝트 루트에 빈 파일
  **`NEW_SESSION_REQUESTED`**를 만들어 둔다. 다음 기동 **딱 1회만** 새 대화로
  시작하고 플래그는 즉시 삭제되어, 그 다음부터는 다시 자동으로 이어간다.
  (`STOP_SIGNAL`과 완전히 같은 방식. 둘 다 `.gitignore` 대상 — 커밋되면
  체크아웃마다 되살아나 매번 대화가 끊긴다.)
  ```
  New-Item "NEW_SESSION_REQUESTED" -ItemType File
  ```
- **대화 내용은 PC를 꺼도 사라지지 않는다.** 메시지마다
  `~/.claude/projects/<프로젝트>/<세션ID>.jsonl`에 즉시 기록된다(OneDrive 폴더
  **밖**이라 동기화 충돌과도 무관). PC를 끄면 "일시 중단"이지 "소실"이 아니다.
- **자동 재시작**: 모바일에서 세션 '종료'를 눌러도(실수로 두 번 눌러도) 런처가
  5초 뒤 새 세션을 자동으로 띄운다(최대 30회). 예전엔 여기서 창이 프롬프트에
  멈춰, PC 앞에 사람이 없으면 그날 내내 폰 접속이 끊긴 채 방치됐다.
  **완전히 끄려면 PowerShell 창 자체를 닫을 것** — 모바일 '종료' 버튼은 세션만
  끝낼 뿐 창을 못 닫는다. 5초 미만 즉시종료가 3회 연속이면 클릭 실수가 아니라
  설정/인증 문제로 보고 자동재시작을 멈춘다.
- **감시**: `main.task_remote_control_watchdog`가 09:06에 1회 프로세스 존재를
  확인해, 없으면 텔레그램(signal)으로 알린다. 매매와는 완전히 별도 프로세스라
  원격제어가 죽어도 **봇 매매에는 영향이 없다**(알림 목적은 "오늘 폰으로 못 본다"를
  그날 안에 아는 것).

\### 🆕 대시보드 (2026-08-11 신설, Phase 0 — 읽기 전용)

```
run_dashboard.bat          (또는  python -m ui.server)
-> http://127.0.0.1:8787
```
`ui/` 폴더. **관측 전용이고 주문·설정변경 기능이 하나도 없다.**
상세는 `ui/README.md` — 아래는 봇을 만질 때 알아야 할 것만.

- 🔴 **`ui/`는 `core/`·`main.py`를 절대 import하지 않는다.** 그래서 UI를
  아무리 고쳐도 15개 스위트 1,660건에 영향이 없고 **장중에도 UI만은 안전하게
  수정할 수 있다.** 허용 의존은 `db.connection`(설정·풀 단일 출처) + 표준
  라이브러리뿐이다. 이 규칙이 깨지면 Phase 0의 안전성이 통째로 사라진다.
- **봇과 별도 프로세스**다. UI가 죽어도 봇은 살고, 봇이 죽어도 UI로 원인을 본다.
  DB 커넥션은 `readonly=True` 세션이라 실수로 UPDATE를 써도 **DB가 거부**한다.
  기본 바인딩은 **루프백(127.0.0.1)** — 실계좌 현황을 LAN에 노출하지 않는다.
- **핵심 기능은 「🔬 장중 관찰 체크리스트」**다. 이 문서의 순위 0~10 표를
  자동 판정한다(`ok/warn/bad/**na**`). 🔴 **`na`(판정 불가)를 성실히 쓴다** —
  데이터가 없는데 초록불을 켜면 표가 없는 것보다 나쁘다.
  ⚠️ **08-11 날짜로 열면 0번·3번이 '이상'으로 뜨는 게 정상**이다(그날은 옛
  조건식·손절 -3%로 돌았다). **08-12부터 '정상'이어야 한다.**
- 🔴 **데이터 함정 3가지**(실측 확인, 분석할 때도 그대로 적용된다):
  ① `system_events.timestamp`는 **UTC**인데 `trades.buy_time`은 **KST**다
     (실측: 뉴엔AI 손절이 13:51:44 vs 04:51:44). **섞으면 9시간 어긋난다.**
  ② **추가매수는 `entry_reason`을 덮지 않는다** — 뉴엔AI가 17주+17주=34주가
     됐는데 `entry_reason`엔 최초 진입 문구만 있다. 즉 **물타기 발동은
     `trades`로 셀 수 없고** 로그(`💧 물타기`)나 `system_events.BUY_ADD`를 봐야 한다.
  ③ `watch_list_log`의 `surge_rate`/`open_price`/`today_open`이 **전부 NULL**이다.
     그래서 체크리스트 0번이 "편입 등락률 8%" 대신 **조건식 이름 확인**으로 갔다.
- 🆕 **매매일지 자동저장** — `python daily_journal.py`(별도 프로세스, 봇 코드 0줄).
  하루치를 `observations/journal/YYYYMMDD.json`에 굳힌다(약 33KB/일).
  · **왜 필요한가**: DB는 매매 기록을 영구 보관하지만 **물타기 발동 횟수·수동
    추가매수 감지는 로그에만 남고**, 로그는 10MB에서 로테이션되어 사라진다.
    며칠 지나면 그날 판정을 **원리적으로 재현할 수 없다.**
  · 대시보드는 **과거 날짜면 스냅샷을 우선**한다(로그가 살아있을 때 굳힌 값이라
    지금 다시 계산한 것보다 정확하다). 오늘은 항상 실시간 계산이다.
  · 실측: 백필하면 과거로 갈수록 `판정 불가`가 는다(08-11 1건 -> 07-30 5건) —
    로그가 사라진 것이고 **그게 정확한 상태다**(0으로 뭉개지 않는다).
  · 스케줄러 등록은 **아직 안 했다**. 하려면 15:40(봇 자동종료 15:33 뒤):
    `schtasks /Create /TN "AutoTrader_Journal" /SC DAILY /ST 15:40 /TR "cmd /c cd /d C:\AutoTrader_Bot\ProjectRoot && python daily_journal.py"`
- **Phase 1(전략 파라미터 토글)은 아직 없다.** 하려면 `strategy_overrides`
  테이블 + `task_config_watch` + `apply_overrides()` **단일 관문**이고,
  관문의 불변식은 감사(`audit_20260805` / `audit_deep_20260808`)에 이미 있는
  것을 재사용할 것. 🔴 근거: `strategy_manager`가 상수를 **메서드 안 모듈
  전역**으로 읽어(`if AVG_DOWN_ENABLED and ...`) `setattr`이 **재시작 없이 먹는다**.
  단 ⓐ 파생 상수(`TAKE_PROFIT_CAP`은 `EXIT_POLICY`를 고쳐도 안 바뀐다)와
  ⓑ 포지션에 박히는 값(`pos["stop_rate"]`는 신규 매수분부터)이 예외다.
